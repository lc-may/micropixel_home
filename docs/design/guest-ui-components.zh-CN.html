01 / DECISIONS

设计目标与核心决策

公共 UI 能力从真实应用的重复代码中提取。首批目标应用是天气、新闻、时钟闹钟和网易云音乐；优先减少页面头部、选项切换、可见行复用、触摸取消和内容状态展示的重复实现。

  1. 在现有 Scene UI 之上组合。复用 SDK 的基础节点、控件、布局和事件，保持 Guest 与 LVGL 类型隔离。
  2. 先有明确的重复行为，再形成公共 API。一个 App 内先抽局部组件；第二个具有不同业务的数据源验证边界后，再沉淀通用部分。
  3. 优先补行为契约。布局、事件消费、触摸取消、数据身份和资源所有权，都属于组件抽象的一部分。
  4. App 保留业务决策。网络、Job、消息、存储、筛选规则、收藏确认和导航目的地由应用处理。
  5. 首批采用 AppBar、SegmentedControl、VirtualList。同时统一现有按钮的状态行为；Theme、ListItem 和内容状态展示随真实迁移逐步完善。
  6. 保持现有 ABI。首批组件仅组合 Guest Scene 和输入事件，不增加 Core import、Service ID 或 raw LVGL 跨界调用。
术语与实现状态

本文的 UI widget 指页面中的可复用控件，与 app.widgets() 发布到 Home 的 Widget 数据快照是不同概念。首批 AppBar、SegmentedControl、VirtualList、ContentStateView、Theme 和 ComponentRoot 已位于 guest/sdk/ui/，由天气、闹钟和音乐使用。新闻迁移、可变行高、骨架与组件内重试动作属于后续扩展。

本设计与已有音乐 UI 控件契约配合使用。已有 Slider、IconButton、ListItem 和 ScrollView 的行为应在迁移中保留；页面视觉继续遵循家庭面板界面规范。

3.1 Guest UI 的边界

公共组件位于 guest/sdk/ui/，依赖 SDK 公共节点和输入事件。组件头文件不包含 LVGL、ESP-IDF 或板级类型；不把 lv_obj_t*、LVGL style、Host 指针或 C++ 对象布局送过 ABI。

Runtime 继续负责 SDK 到 wire 的转换。Host 继续管理资源隔离、图形合成和生命周期校验。当前 Scene Runtime 会编码与提交场景，GuestGraphicsEngine 使用 App Surface 合成；Scene 节点并不要求逐个映射成 LVGL 原生 widget。

3.2 Host raw LVGL 的复用范围

PC Home、应用市场、系统弹窗等 Host UI 的 raw LVGL 调用可以在 Host UI 目录内提取构造与样式 helper。它们遵循 Host 的线程、内存和系统交互约束；与 Guest 组件共享视觉含义和资源规范，不共享可变对象或运行时指针。

3.3 组合方式

组件通过持有根 Container 和成员控件形成子树，采用值类型、显式方法和类型明确的动作。首批不要求引入通用 Widget 虚基类、全局控件注册中心或新的响应式渲染运行时。已有 content() 等子容器入口可作为局部自定义扩展点。

与 App 生命周期的关系

Activity 负责页面组件的创建、事件转交和销毁；Service 通过 Model 提供数据。公共 UI 组件不持有 Activity/Service 指针，不自动启动网络、Job 或应用导航。

04 / COMMON CONTRACT

公共组件接口契约

首先统一语义，再逐步统一接口形状。现有 ButtonUpdate、ScrollUpdate、ListItemUpdate 可以由适配层转换；迁移期间保留原有入口，不要求一次替换所有 SDK 控件。

能力组件契约
创建接收父 Container、局部 bounds 和必要样式。新复合组件使用 Result<T> 返回自身的参数、布局或资源失败，RAII 清理已建子树。委托的既有 TextButton、ScrollView、MaterialIconButton 与行工厂仍遵循既有分配失败即 panic 的策略；第一版不承诺所有底层分配失败均可恢复。
布局AppBar 和 VirtualList 的 SetBounds 更新布局与命中区；失败保留原布局。SegmentedControl 的选项几何在创建时固定。父容器的平移和裁剪由 Scene 统一处理。
数据明确属性是否复制、借用和受何种长度限制。长期保存的文本使用组件自有存储，或要求调用方保证完整寿命。
可见与禁用隐藏不参与输入；禁用不发出动作。隐藏、禁用、数据身份变化和页面失焦都取消未完成手势。
事件结果区分 handled、changed 和组件自己的 typed action；无动作时用显式空值，不使用业务 ID 的特殊数值代替。
清理CancelInput 仅清除输入；Destroy 结束组件子树，重复调用安全。析构 best-effort，不使用失败的 value() 导致清理阶段 panic。
提交组件修改 Guest 节点，不自行 Present。页面汇总 changes 后在当前事件末尾提交；提交失败遵循已有 Scene 重试与旧画面保留契约。
C++ · component.hpp
template <class Action>
struct UiUpdate {
    bool handled{};                  // 本手势或事件已被该组件接管
    bool changed{};                  // 本次调用改变了可见 UI
    std::optional<Action> action;    // 请求 App 执行业务动作
};

4.1 changed 与 handled 的区别

一次点击可以在没有按下视觉变化时发出 action；一次滚动可以 changed=true 而没有业务 action；一次边界拖动即使偏移未改变，仍然 handled=true。上层不能只看 changed 决定是否继续把触摸交给后面的组件。

4.2 外部控制的业务状态

收藏、播放、筛选与导航是否成功由 App 决定。组件可以表现 pressed、pending 或 selected，但网络确认前不自动提交收藏业务状态。SegmentedControl 的点击返回选择请求；应用接受后调用 SetSelected，保持与已有 IconButton 的状态契约一致。

4.3 更新合并

属性不变时避免重复文字测量、重新绑定和节点创建。组件级 changed 用于页面调度；Scene 原有的净变化合并继续负责实际提交。两层语义不互相替代，也不引入组件自己的 Timer。

05 / INPUT

触摸路由与手势仲裁

复合组件需要提供完整的一次手势行为。命中某个矩形只是起点，还要定义后续 Move、Up、Cancel、多触点和父容器滚动怎样处理。

  1. 从最上层可见交互开始页面的弹层先处理输入；同级组件按明确的交互优先级分发。已接管手势的 owner 持续接收该 touch ID 的后续事件。
  2. Down 建立候选捕获保存 touch ID、坐标、行数据身份及命中区域。列表可以同时记录潜在的行点击和潜在滚动，但对外只有一个列表 owner。
  3. 超过滚动阈值时交给滚动继承现有 ScrollView 的阈值语义，向候选行取消按下状态。手势进入拖动后不会因为手指回到起点而重新成为点击。
  4. Up 根据 owner 收束滚动手势消费松手，禁止穿透到行；点击候选只有在身份、代次和命中仍有效时才发出一次动作。
  5. Cancel 与外部变化统一处理页面隐藏、禁用、数据更换或根节点销毁都取消捕获；后续迟到的 Up 不再产生动作。
Idle→ DownPendingTap→ Move 超阈值Dragging→ Up / CancelIdle，无点击

PendingTap 也可以在有效 Up 时返回一次点击并回到 Idle；任何状态的 Cancel 都不产生动作。边界处没有实际滚动位移，仍应遵循已进入 Dragging 的手势归属。

5.1 正文与尾部动作

保留 ListItem 现有的独立命中区：歌曲正文点击打开或播放，尾部按钮点击收藏；尾部动作不冒泡成正文动作。父容器因滚动接管手势时，两类子区域都取消。

5.2 坐标与多触点

对外接收 Scene 逻辑坐标的 TouchEvent，每一层通过自己的容器变换到局部坐标。上层不重复应用屏幕缩放。组件单次手势只跟踪一个 touch ID；其他触点不能接替已有捕获，也不能结束原手势。

5.3 输入重置范围

App 只调用最外层组件的 CancelInput。组件内部负责向自己组合的按钮、滑块和列表传播；不需要把所有控件登记到跨 App 的全局对象树。系统 Home、Back 手势和音频焦点仍由既有 Host 与页面约定处理。

06 / VIRTUAL LIST

VirtualList：复用机制与稳定数据身份

VirtualList 是首批行为抽象的重点。它组合 ScrollView 和一个预先确定容量的可见项池；App 提供数据数量、稳定 key、绑定逻辑和动作处理。行可以是现有 ListItem，也可以是 App 自己的 NewsCard。

6.1 第一版处理固定行高

新闻卡片和歌曲行已有固定纵向步长，适合作为首批消费者。设行高为 h、间距为 g、总数为 n，则步长 s=h+g；非空内容高度为 n×h+(n−1)×g，空列表高度为 0。首个候选可见行由 floor(offset/s) 得到，再结合 viewport、边界与 overscan 得出绑定范围。

计算使用足够宽的中间整数，检查零尺寸、溢出、数据规模与 Scene 坐标上限。可见池包含边缘部分可见行；池及身份数组只在创建时一次分配到堆，由 unique_ptr 持有，避免大容量返回值占满 Guest 的 16 KiB 栈；容量由 viewport、步长与 overscan 推导并在创建或布局调整时检查。容量不足返回明确错误，不能静默留下可见空洞。

滚动主要更新 content 平移；只有绑定身份或显示数据版本变化时才重绑行。池大小与可见工作集有关，节点数不随总数据量线性增长；绘制与拖动不创建新控件。

6.2 key、数据集代次与绑定代次

slot 是可复用的 UI 位置，key 才是业务身份。新闻可以提供 article.key，音乐提供 track.id；城市提供稳定目录身份。key 在同一逻辑数据集中唯一，不能简单使用滚动后的 slot 编号。重复 key 应在绑定边界被拒绝或诊断。

数据集 generation 区分来源切换、账号切换、替换与筛选结果重建。第一版在每个 slot 保存 index、key 和 generation；任何重绑都立即取消该 slot 的捕获。Down 保存 touch ID 与 {slot, key, generation}，Up 再验证身份与区域。即使一个 slot 先后从 A 变为 B 又回到 A，原手势已取消，也不会恢复。

6.3 数据更换与追加

替换数据集显式更新 generation，取消所有手势，并按页面策略回顶或恢复稳定 key 的锚点。第一版允许回顶；恢复锚点属于明确的后续能力，不默认承诺。向当前数据集追加时保留偏移与现有 key，不把它误判为完全替换。

仅改变未命中项的展示数据不必取消全列表，但命中项删除、身份变化、布局变化或可操作状态变化必须取消对应捕获。若实现阶段无法可靠区分，第一版采用更保守的数据变更取消策略。

6.4 城市网格与长文

同一 VirtualList 已通过 ListGeometry 的 columns、column_gap 和 row_gap 表达固定列数网格。天气使用三列 TextButton、18 个池槽；音乐使用单列 ListItem、8 个池槽。两者共享身份校验与手势仲裁。

新闻正文当前有逐行测量和分批排版。第一版 VirtualList 不承诺支持任意高度内容或文本排版；未来若需要可变行高，应单独定义高度缓存、可见范围查找与滚动锚点契约。

07 / COMPOSITE COMPONENTS

其他公共组件的职责

7.1 AppBar

组合标题、可选副标题、可选 leading 操作和一组有界 trailing 操作。通过父 bounds、内边距、间隔和触摸尺寸计算布局；为操作先预留空间，再确定标题最大宽度。支持无 leading 的天气主页面，以及有返回按钮的城市选择、正文等页面。

输出 AppBarEvent，其 kind 为 kLeading、kTitle 或 kAction；尾部动作带 index，由调用方映射到业务。最多支持一个 leading 和两个 trailing 动作。AppBar 不自行导航，不知道“刷新天气”“添加闹钟”或“关闭新闻正文”的业务含义。标题、副标题与文字动作限 128 UTF-8 字节，由 Scene 复制；超长更新返回错误。标题区域先扣除动作和副标题宽度，再进行裁剪，避免遮挡操作。

7.2 SegmentedControl

组合一组可选项，统一命中区域、当前索引、禁用项、选中样式和取消行为。第一版用于天气城市分类与音乐底部导航，使用 normal / selected 样式和可选下划线标记。

选中态由 App 设置。第一版重复点击已选项仍返回索引；是否刷新或保持当前页面由 App 解释。列表筛选后是否回顶由 App 调用列表接口完成。

7.3 ListItem 与内容槽

第一版复用现有 ListItem 的 leading、双行正文和独立 trailing 动作，不改变其内容槽接口。可选附件和提醒行的进一步统一需有真实消费者再扩展。

新闻两行大标题、排名徽章、热度与骨架的组合继续由 NewsCard 表达；天气每日预报的温度范围条继续留在应用内，可进一步组织为 DailyForecastRow。公共 Card 可提供背景和内容容器，但不把所有业务卡片塞进一个包含大量布尔开关的类型。

7.4 ContentStateView

第一版输入为 ContentState {phase, has_content, message, detail}。无内容时显示等待、空或错误文字；has_content=true 时隐藏提示层，保留 App 已有内容。message / detail 各限 256 UTF-8 字节，Scene 复制文本，非法更新保留原展示。

Empty 由业务完成后无内容决定，不能在第一次请求尚未结束时误显示。重试入口目前复用 AppBar 刷新动作，缓存更新提示由 App 自己的状态栏提供。骨架、内联重试按钮和 RetryRequested 是后续方向；HTTP、Job、重试次数、退避和缓存有效性始终由 App 管理。来源署名与业务统计仍由页面提供。

音乐MiniPlayer、完整播放器、登录视图可复用的图文布局和动作组；不携带音乐服务模型。
08 / THEME & LAYOUT

主题、布局与文本策略

8.1 从现有 panel 定义整理 Theme

以 panel.hpp 和家庭面板视觉规范为起点，整理颜色角色、文字角色、内边距、组件间距、圆角和最小触摸尺寸。现有 720×720 设计的 24 边距、84 触摸尺寸是默认 profile 的参数，不写死在公共组件算法里。

第一版使用明确传入的样式快照，保持创建和更新的成本可见。panel 的既有常量可作为默认主题兼容入口；运行时全局主题广播、复杂层叠样式和自动资源重建留待实际需求出现后定义。

8.2 布局与坐标

组件接收局部 Rect，组合现有 Flex/Grid 计算。公共组件不调用 ConfigureDisplay，不持有全屏分辨率假设；Activity 在合适的一次性初始化位置配置逻辑画布，页面依据 RendererInfo 与 safe area 分配组件区域。

布局失败、文本超出可分配区域或触摸目标冲突时，返回清晰错误或采用已声明的降级。新增 bounds 时同时更新绘制和命中区域；视觉按钮可以小于触摸目标，但相邻动作不能因隐式扩张而产生重叠。

8.3 文本测量与溢出

复用 Label、text_overflow.hpp 和 wrap_text.hpp 的测量、UTF-8 与折行能力。字符或字节截断用于存储边界，像素测量用于显示边界；两者分别定义。字体角色由 Host 提供，不能假定所有平台有相同字宽。

标题、列表正文和状态文字分别声明最大存储长度、行数和溢出策略。文本、字体、可用宽度或显式排版版本变化时重新测量；内容未变的滚动不重复排版。应用特有的标题清洗与网络内容校验仍留在 App。

09 / OWNERSHIP

资源所有权与生命周期

Scene 持有节点状态，复合组件持有自己根子树的清理责任和输入状态。根节点句柄不是独立的 Host 对象指针；组件不延长 Scene、图集或 Application 的有效寿命。

对象或操作生命周期要求
组件与根子树新复合组件不可复制、可移动。Destroy 先取消手势，再释放自己的根子树并清空句柄；重复 Destroy 不产生额外操作。
移动语义移动后仅目标对象保留清理责任，源对象为空。移动赋值先清理目标旧子树；不能只复制 ContainerNode 后让两个析构路径都认为自己拥有子树。
父容器与 Scene页面优先先销毁组件再销毁 Scene。父子树已清理时，组件的后续清理必须识别无效句柄，不对失效节点调用视觉 setter。
共享图集默认由 Activity 级资源对象持有，多个组件借用；组件结束不主动释放他人的图集。资源身份与使用寿命遵循现有 SDK 契约。
组件资源域在 Activity 回调中创建的 UI 资源保持 Activity 域归属。把句柄 move 到另一个对象不会改变原来的资源域。
文本、数据与回调绑定回调不保存临时数据 view。组件保存自己的有界显示值或借用具有明确寿命的数据源；不隐式捕获已结束的 Activity、请求或栈对象。

9.1 Activity 集成

OnCreate 创建组件和首帧；OnEvent 转交输入、处理 typed action、更新 Model 并合并提交；OnStop 调用 CancelInput；OnResume 同步当前 Model 并按需绘制；OnDestroy 结束页面组件与页面资源。Activity 重建后重新绑定，旧节点和手势状态不复用。

9.2 有界资源成本

组件创建、显式布局调整或更换容量时可以申请必要存储，并处理失败。常规事件、绘制和滚动复用节点与工作区；不依赖频繁创建/销毁控件实现选中效果，不为每个列表项目建立常驻节点。

容量由使用者和组件参数明确约束，不能把 PC 可用内存当成 MCU 预算。模板可用于编译期容量和行类型，但应控制实例化规模；无需求时不增加 type-erasure、隐式堆分配或跨层共享所有权。

10 / EVOLUTION

兼容策略与演进顺序

保留现有 Scene、基础控件与调用方式。新增组件先在局部页面接入，应用行为和公共契约稳定后再迁移其他页面。每个阶段以明确的消费者为依据，避免先构造一个尚无真实调用者的完整框架。

应用公共组件与页面边界
天气weather_activity.hpp 管理预报；city_picker.hpp 使用 AppBar、SegmentedControl<2> 和 VirtualList<TextButton,18>。weather_model.hpp / weather_service.hpp 独立维护缓存、Job 与 Widget。
闹钟clock_activity.hpp 使用 AppBar；clock_page.hpp 持有本页 ComponentRoot 与 ContentStateView。planner.hpp / clock_service.hpp 负责持久计划与导航消息。
音乐music_view.hpp 使用 AppBar、SegmentedControl<3>、VirtualList<ListItem,8> 和 ContentStateView。账号、协议、播放队列和 PlaybackService 继续由业务层持有。
后续方向新闻接入同一组件；先评估固定卡片，再考虑可变行高、稳定锚点、更多内容槽和内联重试。

10.2 协议和平台兼容

首批能力在 Guest 内实现，保持 Graphics ABI、Core import 和 Bundle 外壳。若新组件遇到现有节点无法表达的实际能力，先记录具体调用场景和成本，再单独设计服务扩展；不直接把 raw LVGL 调用穿过边界。

组件库与 App 的 Activity/Service 模式相互独立：可组合到 Run() 前台应用，也可组合到当前 PC 的 RunComponents() 应用。MCU 组合根的组件生命周期支持仍以现有平台契约为准，新增 UI 组合不会自动改变该支持范围。

运行、回归与性能测量程序沿用面板运行与验证、图形性能指南和Guest conformance 说明。具体执行记录与交付验收保留在开发记录中。

11 / INVARIANTS

必须保持的不变量与设计取舍

  1. 同一有效手势最多产生一个业务动作；滚动结束与取消不产生行点击。
  2. 尾部动作不同时触发正文；隐藏层、禁用控件和已销毁组件不接收新动作。
  3. slot 复用后，旧手势不能作用于新绑定的数据项；业务动作包含稳定身份。
  4. 组件移动后只有一份清理责任；销毁和重复清理不对失效节点进行修改。
  5. 组件绘制遵循父容器局部坐标、裁剪和逻辑画布，命中区域与布局同步更新。
  6. 未变化属性不触发无意义的重绑、测量和节点创建；页面汇总场景提交。
  7. 列表常驻节点取决于可见池；数据增长不直接等价于 UI 节点增长。
  8. UI 组件不持有网络或业务调度权限，选中与 pending 的最终业务含义由 App 决定。
风险或取舍设计处理
组件 API 因不同页面不断增加开关只提取共同机制；内容通过行类型或子容器组合；差异明显时保持独立组件。
统一结果类型破坏已有调用者先提供适配，保留已有控件契约；新增类型在复合组件层使用。
模板带来 Wasm 体积增长把非行类型相关的范围计算和状态机共享，限制模板仅覆盖必要的容量与绑定部分。
通用布局偏离现有视觉默认主题复现既有页面规范，先迁移结构与行为，再单独评估视觉变化。
更新数据时用户仍在交互使用 key、数据集代次与绑定代次；第一版允许保守取消，不冒险派发旧动作。

保留为后续决策的能力包括：可变行高与滚动锚点、嵌套滚动、统一键盘焦点导航、运行时全局主题切换，以及可跨不同图标渲染方式的更高层 ActionButton。它们需要实际消费者证明边界与成本。
